# Решения по реализации

Фиксируем выборы, сделанные там, где ТЗ допускало варианты (правило 7 из раздела 0).

## 1. Типы БД
`types/database.ts` написан вручную по схеме миграций, доменные типы вынесены в `types/domain.ts`.
Клиенты Supabase не параметризованы дженериком `Database`: вложенные выборки (`select('*, city:cities(*)')`)
без сгенерированных метаданных о связях ломают вывод типов. Результаты запросов приводятся к доменным типам
внутри `lib/queries/*` — UI получает строгую типизацию. После первого деплоя стоит выполнить
`npm run gen:types` и заменить файл сгенерированным.

## 2. Мультиязычные поля
Фолбэк реализован функцией `pick(row, field, locale)`: если `_kk` пустое — показываем `_ru` без каких-либо пометок
пользователю. В админке у каждого поля показывается подсказка «KZ не заполнено».

## 3. Накопительная выдача каталога
Вместо смещения `range(from, to)` страница N возвращает первые `N × 20` записей одним запросом.
Так «Показать ещё» и бесконечная прокрутка работают без дублей при изменении сортировки.

## 4. Кластеризация на карте
Вместо `leaflet.markercluster` (нет поддержки react-leaflet 5) — собственная группировка по городам при зуме < 8.
Пины рисуются через `L.divIcon`, поэтому не зависят от картинок маркеров и красятся по шансу на грант.

## 5. Автопубликация отзывов
RLS запрещает пользователю выставлять `status`, поэтому при включённом `review_auto_publish`
статус меняет Server Action сервисным ключом сразу после вставки.

## 6. Service Worker
Написан вручную (`public/sw.js`) вместо `@serwist/next`: меньше зависимостей и предсказуемая сборка.
Стратегии те же — NetworkFirst для страниц (кэш последних 20), CacheFirst для статики и изображений,
офлайн-страница `/ru/offline`.

## 7. Рейтинг и агрегаты
Считаются триггерами в БД (`recalc_university_rating`, `recalc_university_majors`), а не в приложении:
цифры остаются верными, даже если запись пришла из SQL Editor.

## 8. Загрузка медиа
Логотип, обложка и галерея загружаются прямо из админки (перетаскивание или выбор файла) в бакет
`university-media` через Server Action с сервисным ключом; аватар пользователя — в бакет `avatars`
от его имени, права проверяет RLS. Валидация 5 МБ и JPG/PNG/WEBP продублирована на клиенте и на сервере.
Серверную конвертацию в webp и генерацию трёх размеров не делаем: `next/image` сам отдаёт webp/avif
нужного размера, а лишняя зависимость (sharp) усложнила бы сборку. Оригинал остаётся в хранилище.

## 9. Демо-отзывы в сиде
`reviews.user_id` ссылается на `profiles`, а профили создаются только при регистрации, поэтому синтетические
отзывы в `seed.sql` не создаются. Первые отзывы появляются после регистрации живых пользователей.

## 10. Просмотры ВУЗов
Счётчик `views_count` увеличивается серверным обработчиком `/api/track` при событии `university_view`
(RPC `increment_university_views`), а не из браузера напрямую.

## 11. Аватары пользователей убраны
Загрузка фото в профиле и бакет `avatars` больше не используются: лишние файлы и трафик
на старте не нужны, вместо фото показывается первая буква имени. Поле `profiles.avatar_url`
и политики бакета в миграциях остались — вернуть загрузку можно одним компонентом.

## 12. Вход только по почте
Кнопка «Войти через Google» убрана с форм входа и регистрации: настройка OAuth требует
проекта в Google Cloud и тормозит запуск. Серверное действие `signInWithGoogle` осталось
в `lib/actions/auth.ts` — чтобы вернуть кнопку, достаточно снова вызвать его из формы.
Вход по SMS по-прежнему готов и включается флагом `auth_phone_enabled`.

## 13. Фокус в диалогах
Эффект `useDialogBehaviour` зависел от `onClose`, который родитель пересоздаёт на каждый рендер.
Из-за этого при вводе каждого символа эффект перезапускался и возвращал фокус на первую кнопку —
в форме отзыва можно было напечатать только одну букву. Теперь эффект зависит только от `open`,
а `onClose` живёт в ref. На это есть регрессионный тест `tests/dialog-focus.test.tsx`.

## 14. Кэширование публичных данных
Справочники, настройки, карточки ВУЗов, карта и список программ читаются публичным клиентом
без cookie и кэшируются через `unstable_cache` (сутки для справочников, час для остального).
Админка при сохранении сбрасывает кэш по тегам `universities`, `majors`, `dictionaries`, `settings`,
поэтому правки видны сразу. У публичного клиента таймаут 8 секунд: если база не отвечает,
страница отдаёт пустой список, а не висит.
